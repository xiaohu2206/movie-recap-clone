## 3. 步骤 5.1：原片字幕补充（Movie Subtitle Filler）

### 3.1 输入 / 输出
- 输入：`--script-mapping outputs/5_script_visual_binder/script_mapping.json`、`--movie-path <原片>`、可选 `--movie-subtitle-srt <现成原片字幕>`。
- 输出：`outputs/5.1_movie_subtitle_filler/script_mapping_subtitled.json`、`outputs/5.1_movie_subtitle_filler/movie_subtitle.srt`。

### 3.2 核心逻辑
1. 收集所有段所有 `movie_time_ranges` 的时间区间，取并集并合并相邻窗口（padding 0.3s），得到"需要原片字幕的时间窗"。
2. **获取原片字幕**（两档，复用现有能力）：
   - 有 `--movie-subtitle-srt`：直接 `parse_srt()`（最快，MVP 首选，和第 1 步 `--subtitle-srt` 同款思路）。
   - 无现成字幕：对原片做 ASR。MVP 可整片 `extract_srt_with_bcut(movie, movie_subtitle.srt, work_dir)`；优化版只对并集窗口用 `extract_audio_mp3` 抽音频后分窗 ASR，降低长片成本。
3. 给每个 range 补两个字段（对齐设计第三节）：
   - `clip_index`：**段内**顺序号（0,1,2…），供 5.2 返回切分点。
   - `movie_subtitles`：与该 range 时间重叠的原片字幕条目（`[{start,end,text}]`）。重叠判定复用 `shot_breakdown._subtitle_text_for_range` 同款规则：`sub.start < clip.end and sub.end > clip.start`。
4. 把（合并去重后的）原片字幕写出 `movie_subtitle.srt`（复用 `write_srt`），供 `shot_breakdown`、字幕展示复用。

### 3.3 输出结构示例

## 4. 步骤 5.2：原声判定（Audio Role Classifier）

### 4.1 输入 / 输出
- 输入：`--script-mapping outputs/5.1_movie_subtitle_filler/script_mapping_subtitled.json` + AI 参数（与第 6 步同款 `--api-key/--base-url/--model/--temperature`）。
- 输出：`outputs/5.2_audio_role_classifier/script_mapping_with_audio.json`。

### 4.2 设计取向：以 LLM 为主，规则只做"极廉价短路"
> 原则：**判定交给 LLM，规则只负责省掉那一种零信息、零歧义的情况**，不参与任何"前/后/混合/重合度"这类语义判断（这些都容易误判，正是 LLM 该做的）。

规则层**只保留唯一一条短路**：
- 一段内**所有** range 的 `movie_subtitles` 全为空 → 直接判 `all_narration`，不调 LLM。

> 理由：没有任何原片台词时，必然是纯解说，没有歧义；这是唯一能安全跳过 LLM 的情况，同时也能显著减少调用量（解说视频里大量段落本就无原片台词）。

**其余全部交 LLM**，包括过去想用规则拍板的"前空后有 / 前有后空 / 全有且高重合"——这些都改由 LLM 判断 `audio_pattern` 与切分点，避免规则误判。

### 4.3 LLM 判定（主路径，复用第 6 步同款 AI 通路）
复用 `utils.ai.CustomOpenAIProvider + ChatMessage`，照抄第 6 步 `_extract_json()`、`response_format={"type":"json_object"}` 失败回退、批处理写法。System Prompt 用设计第十节（音频结构判断器，四模式、单切点、禁止穿插）。每段 LLM **只返回两个字段**：`audio_pattern` + `split_clip_index`（两部分的 clip 分组由 `run.py` 据此推导，不让 LLM 输出冗余信息）。

LLM 解析失败/返回非法时的兜底（保守）：该段降级为 `all_narration`（宁可配音，不误放无关原声），并在 `audio_backend.fallback` 计数，便于排查。

#### 4.3.1 LLM 输入 / 输出 / 解析（具体逻辑，落在 `classifier_llm.py`）

**(1) 给 LLM 的输入**：只喂判定必需的最小信息，按段（可批量打包多段）。每段只给 `segment_id` / `old_text`（整段旧解说）/ `clips`（按 `clip_index` 排序，每个 clip 只给时间与原片字幕文本）/ 允许的四种模式。对应设计第五节：

```json
{
  "task": "decide_audio_pattern",
  "rules": [
    "不能改变镜头顺序，不能改 clip 的 start/end",
    "一个 segment 内最多只能切一次（单切分点）",
    "禁止 解说→原声→解说 或 原声→解说→原声 的穿插",
    "movie_subtitles 像角色对白且与 old_text 高度重合 → 原声；为空 → 解说；旁白/情绪/剧情解释 → 解说"
  ],
  "allowed_audio_patterns": [
    "all_narration", "all_original_audio",
    "narration_then_original_audio", "original_audio_then_narration"
  ],
  "segments": [
    {
      "segment_id": "seg_001",
      "old_text": "职场如战场而他是那个最没用的炮灰……我只是没能力从小到大我最会的就是拼命",
      "clips": [
        { "clip_index": 0, "start": 149.22, "end": 152.587, "movie_subtitles": [] },
        { "clip_index": 1, "start": 155.722, "end": 157.978, "movie_subtitles": [] },
        { "clip_index": 2, "start": 160.234, "end": 163.399, "movie_subtitles": [] },
        { "clip_index": 3, "start": 344.37,  "end": 352.585, "movie_subtitles": ["因为你业绩差又不努力", "我不努力？", "我只是没能力"] },
        { "clip_index": 4, "start": 352.681, "end": 353.59,  "movie_subtitles": ["从小到大"] }
      ]
    }
  ],
  "output_schema": {
    "results": [
      { "segment_id": "seg_001", "audio_pattern": "narration_then_original_audio", "split_clip_index": 3 }
    ]
  }
}
```

Prompt 组装（与第 6 步同结构）：`messages = [system(设计第十节判断器规则), user(json.dumps(上面 payload))]`，调用时带 `extra_params={"response_format": {"type": "json_object"}}`，失败则去掉该参数重试一次。

**(2) LLM 期望输出**（只输出 JSON，不要解释文字）：

```json
{
  "results": [
    { "segment_id": "seg_001", "audio_pattern": "narration_then_original_audio", "split_clip_index": 3 }
  ]
}
```

> 字段说明：`split_clip_index` = **第二部分起始的 clip_index**（`*_then_*` 时有效）；`all_narration` / `all_original_audio` 时给 `null`。clip 分组完全由 `audio_pattern` + `split_clip_index` 推导，无需 LLM 再回传索引数组、confidence、reason。

**(3) 解析与校验**（`classify_segments` 内，复用第 6 步 `_extract_json`）：
- `_extract_json(response.content)` 取 `results` 数组，按 `segment_id` 建字典，每项只读 `audio_pattern` + `split_clip_index`。
- 逐段**校验后推导分组**（防止 LLM 乱给；非法即该段兜底 `all_narration`）：
  - `audio_pattern` 必须 ∈ 四种枚举，否则兜底。
  - `all_narration` → narration 组 = 全部 clip，original 组 = `[]`。
  - `all_original_audio` → 反之。
  - `narration_then_original_audio` → `split_clip_index` 必须满足 `0 < split < clip 数`，否则兜底；narration 组 = `clip_index < split`，original 组 = `clip_index >= split`。
  - `original_audio_then_narration` → 同上但前后角色对调。
- 校验通过后由 `run.py` 落地：
  - 段级写 `audio_pattern / split_clip_index / narration_part / original_audio_part`；
  - `original_audio_part.subtitles` = original 组各 clip 的 `movie_subtitles` 文本拼接；`narration_part.old_text` 由 `run.py` 按 narration 组 clip 的时间占比从整段 `old_text` 近似切分（见下方注意）；
  - 按组把每个 range 回写 `audio_role`（`narration` / `original_dialogue`）与 `audio_action`（`narration` / `keep_original_audio`）。

**(4) 函数签名建议**：

```python
# classifier_llm.py
async def classify_segments(
    segments: list[dict],          # 规则未短路、需要 LLM 的段（已含 clip_index + movie_subtitles）
    *,
    provider: CustomOpenAIProvider,
    batch_size: int = 8,
) -> dict[str, dict]:              # {segment_id: {"audio_pattern": str, "split_clip_index": int | None}}
    ...
```

> 注意：LLM 输出已简化为只含 `audio_pattern` + `split_clip_index`，不再回传 `narration_part.old_text`。因此把整段 `old_text` 切给 narration 部分这一步放到 `run.py`，按 narration 组 clip 的时间占比近似切分（误差可接受，因为第 6 步仿写本就会重组语言）。

### 4.4 模块内文件拆分（规则与 LLM 各自独立封装）
遵循组件化、逻辑与视图分离、高内聚低耦合（参照 `4_visual_alignment_engine/` 把 recall / solver / refinement 拆成独立文件的既有做法）。`5.2_audio_role_classifier/` 目录内拆成三个文件：

| 文件 | 职责（单一） | 关键导出 |
| --- | --- | --- |
| `rules.py` | **仅规则层**：唯一短路 `all_narration`（全段无字幕）。纯函数、无 IO、无网络。 | `try_shortcut(segment) -> dict | None`（命中返回判定，未命中返回 `None` 交给 LLM） |
| `classifier_llm.py` | **仅 LLM 层**：构造 payload、System Prompt、调用 `CustomOpenAIProvider`、`_extract_json`、批处理、失败兜底。 | `async classify_segments(segments, *, provider/批次参数) -> dict[seg_id, 判定]` |
| `run.py` | **编排层（视图/流程）**：读写 JSON、CLI、`emit_progress`、串联"先 `rules.try_shortcut`，未命中再进 `classifier_llm.classify_segments`"、把判定回写到 `audio_role/audio_action` 与段级字段。 | `main()` |

调用关系：

```text
run.py
  ├─ rules.try_shortcut(seg)        # 命中(全段无字幕) → all_narration，直接出结果
  └─ classifier_llm.classify_segments(未命中的段批量)   # 其余全部 LLM 判定
```

> 好处：规则与 LLM 解耦——以后想加/调规则只动 `rules.py`，想换模型或改 Prompt 只动 `classifier_llm.py`，`run.py` 的流程不变；也方便分别做单测（规则纯函数、LLM 可 mock provider）。

### 4.5 输出结构（关键：同时回写到 range，喂给已有 shot_breakdown）
段级加 `audio_pattern`、`split_clip_index`、`narration_part`、`original_audio_part`；并把判定结果**回写到每个 range** 的 `audio_role` / `audio_action`，字段取值对齐 `shot_breakdown` 已识别的枚举：

```json

      "old_text": "……完整旧解说……",

      "split_clip_index": 3,
      "narration_part":      { "clip_indexes": [0,1,2], "old_text": "……仅解说部分……" },
      "original_audio_part": { "clip_indexes": [3,4], "subtitles": ["因为你业绩差又不努力","我不努力？"] },
      "movie_time_ranges": [
```

## 7. 兜底与风险

| 风险 | 应对 |
| --- | --- |
| 长电影整片 ASR 慢/限速（bcut 在线） | 5.1 只对"绑定 range 并集窗口"抽音频做 ASR；优先支持外部 `movie_subtitle.srt` 直接传入 |
| ASR 文本与真实台词有偏差 | 原声判定用"`old_text` 与 `movie_subtitles` 高重合"启发式 + LLM 双保险，不强依赖逐字一致 |
| 段内被判成"解说→原声→解说"穿插 | 强制单切点（`split_clip_index`），四模式枚举，LLM/规则都不产穿插 |
| 原声片段时长与参考节奏不同 | 原声 item 按原片真实时长走，不 retime（原声本就该按原片） |
| `low_confidence` 的 range | 保守判为 `narration`（宁可配音，避免错放无关原声） |
| 第 8 步拼接缺音轨 | 原声 item 裁剪必须产出 aac 音轨，统一 `-ar 48000`，再 `concat reencode` |
