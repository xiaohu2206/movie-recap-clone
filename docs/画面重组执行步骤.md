# 画面重组执行步骤

## 1. 目标

画面重组用于保留参考视频的完整音频（解说、原声、BGM、音效），再用原片中定位到的画面替换参考视频画面，最终输出剪映草稿、MP4，或两者同时输出。

核心关系是：

```text
参考视频音频 + 原片匹配画面 + 参考视频时间线 = 画面重组结果
```

该模式只处理画面与音频的重组，不执行以下主流程步骤：

- `2_narration_segmenter` 解说段落切分
- `5_script_visual_binder` 解说画面绑定
- `5.1_movie_subtitle_filler` 原片字幕补充
- `5.2_audio_role_classifier` 原声判定
- `6_rewrite_engine` 文案仿写
- `7_timeline_composer` 新解说视频时间线生成
- TTS 配音

## 2. 执行链路

```text
01 参考视频解析
    ↓
03 原片镜头拆分
    ↓
04 画面对齐
    ↓
4.1 参考音频重组
    ↓
08 视频与剪映草稿
```

对应代码目录：

| 步骤 | 模块 | 主要职责 | 关键产物 |
| --- | --- | --- | --- |
| 01 | `1_reference_analyzer` | 提取参考视频字幕、参考镜头、关键帧和时间信息 | `ref_analysis.json`、`ref_subtitle.srt`、`keyframes/` |
| 03 | `3_movie_shot_parser` | 检测原片镜头边界并提取原片关键帧 | `movie_shots.json`、`keyframes/` |
| 04 | `4_visual_alignment_engine` | 将参考镜头匹配到原片镜头，形成画面对齐时间线 | `ref_to_movie_timeline.json` |
| 4.1 | `4.1_ref_audio_rebuild_composer` | 保留参考音频，按对齐结果生成画面重组时间线 | `ref_audio_rebuild_timeline.json` |
| 08 | `8_generate_video` | 按重组时间线切画面、复用音频并输出草稿或视频 | `generate_video_result.json`、草稿、MP4 |

└── movie.srt     # 可选，原片已有字幕；画面重组模式不强制需要
```

先激活项目环境：

```

如果尚未安装环境，可参考根目录 `README.md` 中的 CUDA/PyTorch 安装说明。没有现成参考字幕时，步骤 01 会使用 ASR；参考字幕存在时，建议显式传入 `--subtitle-srt`，可减少识别误差和耗时。

## 4. 推荐：一条命令执行完整重组

```powershell
python .\main.py `
  --pipeline-mode ref_audio_rebuild `
  --ref-video-path .\data\ref.mp4 `
  --movie-path .\data\movie.mp4 `
  --subtitle-srt .\data\ref.srt `
  --render-mode both `
  --video-encoder auto
```

参数说明：

- `--pipeline-mode ref_audio_rebuild`：启用画面重组分支。
- `--ref-video-path`：参考视频路径，既是音频来源，也是未匹配画面的兜底来源。
- `--movie-path`：原片路径，匹配成功后从这里取画面。
- `--subtitle-srt`：参考视频已有字幕时传入；没有时可删除该参数，默认使用 `bcut` ASR。
- `--render-mode both`：同时生成剪映草稿和 MP4；只生成草稿用 `draft`，只生成 MP4 用 `video`，只生成时间线用 `none`。
- `--video-encoder auto`：自动选择视频编码器；也可指定 `libx264` 或 `h264_nvenc`。

需要重新清理所有阶段产物后执行时，加上 `--restart`：

```powershell
python .\main.py `
  --pipeline-mode ref_audio_rebuild `
  --ref-video-path .\data\ref.mp4 `
  --movie-path .\data\movie.mp4 `
  --subtitle-srt .\data\ref.srt `
  --render-mode both `
  --video-encoder auto `
  --restart
```

## 5. 分步执行说明

### 5.1 01：参考视频解析

执行：

```powershell
python .\1_reference_analyzer\run.py `
  --ref-video-path .\data\ref.mp4 `
  --subtitle-srt .\data\ref.srt `
  --output-dir .\outputs\1_reference_analyzer `
  --backend auto
```

没有字幕时：

```powershell
python .\1_reference_analyzer\run.py `
  --ref-video-path .\data\ref.mp4 `
  --output-dir .\outputs\1_reference_analyzer `
  --asr-provider bcut `
  --backend auto
```

主要输出：

```text
outputs/1_reference_analyzer/ref_analysis.json
outputs/1_reference_analyzer/ref_subtitle.srt
outputs/1_reference_analyzer/keyframes/
```

其中 `ref_analysis.json` 是后续步骤的参考时间基准，至少应包含参考镜头的 `ref_shot_id`、`start`、`end` 等信息。

### 5.2 03：原片镜头拆分

执行：

```powershell
python .\3_movie_shot_parser\run.py `
  --movie-path .\data\movie.mp4 `
  --output-dir .\outputs\3_movie_shot_parser `
  --backend auto
```

主要输出：

```text
outputs/3_movie_shot_parser/movie_shots.json
outputs/3_movie_shot_parser/keyframes/
```

`movie_shots.json` 为画面对齐提供原片镜头的起止时间和关键帧检索空间。

### 5.3 04：画面对齐

执行：

```powershell
python .\4_visual_alignment_engine\run.py `
  --ref-analysis .\outputs\1_reference_analyzer\ref_analysis.json `
  --movie-shots .\outputs\3_movie_shot_parser\movie_shots.json `
  --output-dir .\outputs\4_visual_alignment_engine
```

主要输出：

```text
outputs/4_visual_alignment_engine/ref_to_movie_timeline.json
```

该文件是重组分支的核心输入。每一行通常包含：

- `ref_shot_id`：参考镜头 ID
- `ref_start`、`ref_end`：参考视频时间范围
- `movie_start`、`movie_end`：原片匹配范围
- `movie_shot_ids`：命中的原片镜头
- `status`、`confidence`、`match_score`：匹配状态和质量信息

### 5.4 4.1：参考音频重组

执行：

```powershell
python .\4.1_ref_audio_rebuild_composer\run.py `
  --ref-analysis .\outputs\1_reference_analyzer\ref_analysis.json `
  --movie-shots .\outputs\3_movie_shot_parser\movie_shots.json `
  --timeline .\outputs\4_visual_alignment_engine\ref_to_movie_timeline.json `
  --ref-video-path .\data\ref.mp4 `
  --movie-path .\data\movie.mp4 `
  --output-dir .\outputs\4.1_ref_audio_rebuild_composer
```

主要输出：

```text
outputs/4.1_ref_audio_rebuild_composer/ref_audio_rebuild_timeline.json
```

处理规则：

1. 以参考镜头的 `ref_start ~ ref_end` 作为音频时间范围。
2. 对接受的匹配状态（`matched`、`matched_low_confidence`、`inferred_by_neighbors`），使用原片的 `movie_start ~ movie_end` 作为画面来源。
3. 最终每个重组项的时长以参考音频时长为准。
4. 原片画面过长时裁剪；过短时向后扩展，并在产物中记录 `movie_clip_short` 等警告。
5. 默认合并相邻且连续的片段：参考时间间隔不超过 `0.3s`，原片时间间隔在 `-0.2s ~ 1.0s` 之间。
6. 默认吸收不超过 `0.5s` 的短片段，最多向前一个片段扩展 `1.0s`，减少时间线碎片。
7. 未匹配片段默认使用参考视频原画面兜底，音频仍来自参考视频；如果参考媒体范围不足，则会跳过并写入质量报告。

需要调整合并策略时，可使用：

```powershell
python .\4.1_ref_audio_rebuild_composer\run.py `
  ... `
  --disable-merge-adjacent `
  --disable-absorb-short-clips
```

### 5.5 08：生成视频与剪映草稿

#### 同时生成草稿和 MP4

```powershell
python .\8_generate_video\run.py `
  --timeline .\outputs\4.1_ref_audio_rebuild_composer\ref_audio_rebuild_timeline.json `
  --output-dir .\outputs\8_generate_video `
  --ref-analysis .\outputs\1_reference_analyzer\ref_analysis.json `
  --output-root .\outputs `
  --mode both `
  --draft-name RefAudioRebuild `
  --video-output-name ref_audio_rebuild_output.mp4 `
  --video-encoder auto
```

#### 只生成剪映草稿

将 `--mode both` 改为 `--mode draft`：

```powershell
python .\8_generate_video\run.py `
  --timeline .\outputs\4.1_ref_audio_rebuild_composer\ref_audio_rebuild_timeline.json `
  --output-dir .\outputs\8_generate_video `
  --ref-analysis .\outputs\1_reference_analyzer\ref_analysis.json `
  --output-root .\outputs `
  --mode draft `
  --draft-name RefAudioRebuild
```

#### 只生成 MP4

将 `--mode both` 改为 `--mode video`：

```powershell
python .\8_generate_video\run.py `
  --timeline .\outputs\4.1_ref_audio_rebuild_composer\ref_audio_rebuild_timeline.json `
  --output-dir .\outputs\8_generate_video `
  --ref-analysis .\outputs\1_reference_analyzer\ref_analysis.json `
  --output-root .\outputs `
  --mode video `
  --video-output-name ref_audio_rebuild_output.mp4 `
  --video-encoder auto
```

主要输出：

```text
outputs/8_generate_video/audio/
outputs/8_generate_video/shot_breakdown.json
outputs/8_generate_video/ref_audio_rebuild_output.mp4       # video / both
outputs/8_generate_video/generate_video_result.json

```

生成器会根据 `external_audio.start/end` 从参考视频提取音频片段，不会调用 TTS；画面片段则从重组时间线中的 `video_clips` 读取。

## 6. 产物检查清单

执行完成后建议按以下顺序检查：

1. `ref_analysis.json` 中参考镜头数量和参考视频时长是否正常。
2. `movie_shots.json` 是否成功生成，原片镜头数量是否为 0。
3. `ref_to_movie_timeline.json` 中是否存在大量 `unmatched`，以及 `match_score` 是否异常偏低。
4. `ref_audio_rebuild_timeline.json` 的 `quality_report`：重点看 `ready_ref_shots`、`fallback_ref_shots`、`skipped_fallback_no_video_count` 和 `duration_warning_count`。
5. `generate_video_result.json` 中的输出路径是否正确。
6. MP4 是否同时具备画面和参考视频原音频；剪映草稿能否正常打开。

可快速查看质量报告：

```powershell
$p = Get-Content .\outputs\4.1_ref_audio_rebuild_composer\ref_audio_rebuild_timeline.json -Raw | ConvertFrom-Json
$p.quality_report | Format-List
```

## 7. 只重新渲染第 08 步

如果 01～4.1 已完成，只想更换输出模式或编码器，可以复用已有时间线：

```powershell
python .\main.py `
  --pipeline-mode ref_audio_rebuild `
  --render-only `
  --render-mode video `
  --video-output-name ref_audio_rebuild_v2.mp4 `
  --video-encoder auto
```

`--render-only` 要求以下文件已经存在：

```text
outputs/1_reference_analyzer/ref_analysis.json
outputs/4.1_ref_audio_rebuild_composer/ref_audio_rebuild_timeline.json
```

如果只需要生成 4.1 时间线，不需要渲染视频，可执行完整命令时使用 `--render-mode none`，或单独运行 4.1 脚本。

## 8. 与主流程的区别

| 项目 | 主流程 `clone` | 画面重组 `ref_audio_rebuild` |
| --- | --- | --- |
| 音频 | 仿写文案并可能 TTS | 直接复用参考视频音频 |
| 画面 | 原片画面 | 原片匹配画面，未匹配时参考视频兜底 |
| 是否需要 LLM | 第 6 步需要 | 不需要 |
| 是否执行原声判定 | 是 | 否 |
| 时间线 | `final_timeline.json` | `ref_audio_rebuild_timeline.json` |
| 最终入口 | `8_generate_video` | `8_generate_video` |

一句话概括：`4_visual_alignment_engine` 负责“找到原片画面”，`4.1_ref_audio_rebuild_composer` 负责“把参考音频和原片画面排到同一条时间线”，`8_generate_video` 负责“输出草稿或成片”。
