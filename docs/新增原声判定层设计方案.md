可以，你这个思路是对的。

不要在“镜头定位阶段”判断原声，否则会污染定位结果。应该在 **script_mapping 之后** 加一个轻量模块：

```txt
解说画面绑定模块
   ↓
原片字幕补充模块
   ↓
原声/解说判定模块
   ↓
仿稿模块
   ↓
时间轴生成模块
```

核心原则是：

> 镜头怎么匹配，还是按原来的画面定位结果走。
> 是否播放原片，只是后面生成视频脚本时的音频策略，不影响画面定位。

# 一、增加一个模块：原声判定模块

建议模块名：

```txt
Original Audio Decision Module
原声播放判定模块
```

它的作用不是重新匹配画面，而是判断当前 `segment` 里面：

```txt
哪些内容应该仿写成解说
哪些内容应该保留为原片对白/原声
```

但是你有一个很重要的限制：

> 一个 segment 内不能出现：解说 → 原片 → 解说
> 只能是：
>
> 1. 全部解说
> 2. 全部原片
> 3. 前半段原片 + 后半段解说
> 4. 前半段解说 + 后半段原片

这个限制非常好，能让时间轴简单很多。

# 二、调整后的整体流程

```txt
1. 参考视频解析
   - 提取参考视频字幕 old_text
   - 参考视频镜头拆分

2. 解说段落切分
   - 以参考视频镜头聚合字幕
   - 输出 narration_segments

3. 原电影镜头拆分
   - 输出 movie_shots

4. 画面定位
   - ref_shot 对齐到 movie_shot
   - 输出 ref_to_movie_timeline

5. 解说画面绑定
   - old_text + movie_time_ranges
   - 输出 script_mapping

6. 原片字幕补充
   - 根据每个 movie_time_ranges 去原电影字幕里提取原片对白
   - 给每个 movie_time_range 增加 movie_subtitles

7. 原声/解说判定
   - LLM 判断当前 segment 哪部分是解说，哪部分是原声
   - 输出 audio_strategy

8. 仿稿模块
   - 只仿写 narration 部分
   - original_audio 部分不仿写

9. 时间轴生成
   - 根据 audio_strategy 输出最终时间轴
```

# 四、原片字幕补充模块怎么做

这个模块很简单。

你应该提前有一份原电影字幕：

```json
{
  "movie_subtitles": [
    {
      "start": 344.95,
      "end": 347.4,
      "text": "因为你业绩差又不努力"
    },
    {
      "start": 348.2,
      "end": 350.1,
      "text": "我不努力？"
    },
    {
      "start": 350.5,
      "end": 352.5,
      "text": "我只是没能力"
    }
  ]
}
```

然后对每个 `movie_time_range` 做时间重叠匹配：

```txt
如果 subtitle.start < clip.end
并且 subtitle.end > clip.start
说明这条字幕和当前 clip 有重叠
```

伪代码：

```js
function attachMovieSubtitles(scriptMapping, movieSubtitles) {
  return scriptMapping.map(segment => {
    return {
      ...segment,
      movie_time_ranges: segment.movie_time_ranges.map((clip, index) => {
        const subtitles = movieSubtitles.filter(sub => {
          return sub.start < clip.end && sub.end > clip.start;
        });

        return {
          ...clip,
          clip_index: index,
          movie_subtitles: subtitles
        };
      })
    };
  });
}
```

这样做不会影响你的镜头定位，只是给每个原片片段补充字幕信息。

# 七、关键约束：只能有一个切分点

你的限制可以转成一个非常简单的规则：

```txt
一个 segment 里面最多只能切一次。
```

也就是：

```txt
clip 0, clip 1, clip 2 -> 解说
clip 3, clip 4         -> 原片
```

或者：

```txt
clip 0, clip 1         -> 原片
clip 2, clip 3, clip 4 -> 解说
```

不能出现：

```txt
clip 0 -> 解说
clip 1 -> 原片
clip 2 -> 解说
```

所以 LLM 只需要判断：

```txt
audio_pattern 是什么？
切分点 split_clip_index 在哪里？
```

更简洁的输出可以这样：


# 十、LLM 判定 Prompt 可以这样写

```txt
你是影视解说视频的音频结构判断器。

我会给你一段参考视频字幕 old_text，以及这段字幕对应的原电影片段 clips。
每个 clip 里可能包含原电影字幕 movie_subtitles。

你的任务：
判断这段内容里，哪些部分应该作为“解说文案”进行仿写，哪些部分应该保留“原片原声”。

重要限制：
1. 不能改变镜头顺序。
2. 不能改变 clip 的 start/end。
3. 一个 segment 内最多只能切一次。
4. 只能从下面四种模式里选择一种：
   - all_narration：全部都是解说，全部需要仿写
   - all_original_audio：全部播放原片原声，不需要仿写
   - narration_then_original_audio：前面解说，后面原片原声
   - original_audio_then_narration：前面原片原声，后面解说
5. 禁止出现“解说 -> 原声 -> 解说”或“原声 -> 解说 -> 原声”的穿插结构。
6. 如果 movie_subtitles 明显是角色对白，并且 old_text 中包含相同或相近内容，优先判断为原片原声。
7. 如果 movie_subtitles 为空，通常判断为解说。
8. 如果 old_text 是旁白总结、情绪渲染、剧情解释，判断为解说。
9. 如果 old_text 是角色对话、争吵、喊叫、独白，且和 movie_subtitles 接近，判断为原片原声。

只输出 JSON，不要输出解释文字。
```

这个预处理只是为了减少 LLM 犯错，不是必须。

```txt
解说段落切分模块
  - 以参考视频镜头为基准聚合 old_text

原电影镜头拆分模块
  - 生成 movie_shots

画面定位模块
  - 只负责 ref_shot -> movie_shot
  - 不判断原声
  - 不判断仿稿

解说画面绑定模块
  - 生成 script_mapping

原片字幕补充模块
  - 给每个 movie_time_range 添加 movie_subtitles

原声播放判定模块
  - LLM 判断 audio_pattern
  - 输出 all_narration / all_original_audio / narration_then_original_audio / original_audio_then_narration
  - 最多一个 split_clip_index

仿稿模块
  - 只仿写 narration_part
  - original_audio_part 原样保留

时间轴生成模块
  - audio_type = narration 时生成 AI 配音
  - audio_type = original_audio 时播放原片声音
```

最关键的数据结构是：

```json
{
  "segment_id": "seg_001",
  "audio_pattern": "narration_then_original_audio",
  "split_clip_index": 3,
  "narration_part": {
    "clip_indexes": [0, 1, 2],
    "old_text": "需要仿写的解说"
  },
  "original_audio_part": {
    "clip_indexes": [3, 4],
    "keep_original_audio": true,
    "subtitles": ["原片对白"]
  }
}
```

这样你的系统就不会把原声对白误当成解说去仿写，同时也不会影响前面的镜头定位结果。
