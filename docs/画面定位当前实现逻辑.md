# 画面定位当前实现逻辑

本文档记录当前 `4_visual_alignment_engine` 的实际实现逻辑，不是优化方案。

当前画面定位模块的目标是：把参考解说视频里的每个 `ref_shot`，定位到原电影 `movie_shots` 中最可能对应的片段，最终输出：

```text
outputs/4_visual_alignment_engine/ref_to_movie_timeline.json
```

核心入口是：

```text
4_visual_alignment_engine/run.py
align_visual_timeline()
```

当前算法版本为：

```text
visual_alignment_v3
```

## 1. 输入数据

模块主要读取两份上游结果。

### 1.1 参考视频解析结果

来自第 1 步：

```text
1_reference_analyzer/ref_analysis.json
```

运行时通过参数传入：

```text
--ref-analysis
```

代码中读取：

```python
ref_data.get("ref_shots") or []
ref_data.get("ref_video_path")
```

`ref_shots` 中每条数据通常包含：

- `ref_shot_id` / `shot_id`
- `start`
- `end`
- `keyframes`
- `keyframe_times`
- `sample_frames`

### 1.2 原电影镜头解析结果

来自第 3 步：

```text
3_movie_shot_parser/movie_shots.json
```

运行时通过参数传入：

```text
--movie-shots
```

代码中读取：

```python
movie_data.get("movie_shots") or []
movie_data.get("movie_path")
```

`movie_shots` 中每条数据通常包含：

- `movie_shot_id` / `shot_id`
- `start`
- `end`
- `keyframes`
- `keyframe_times`
- `sample_frames`

## 2. 默认运行参数

CLI 默认参数主要定义在 `4_visual_alignment_engine/run.py` 的 `main()` 中。

当前默认值如下：

```text
top_n = 8
min_score = 0.35
keyframes_per_shot = 3
recall_top_k = 80
rerank_top_k = 20
refine_top_k = 3
feature_mode = classic
alignment_mode = temporal
temporal_radius_sec = 1.5
temporal_step_sec = 1.0
neighbor_shot_window = 1
spatial_normalize = auto
device = auto
global_path = enabled
```

几个需要注意的降级逻辑：

- `feature_mode=classic_clip` 目前不会真的启用 CLIP，会回退到 `classic`。
- `alignment_mode=topiq_temporal` 目前不会真的启用 TOPIQ，会回退到 `temporal`。
- `device` 参数目前只写进 metadata，没有驱动实际深度模型推理。

## 3. 总体流程

当前画面定位可以概括为五步：

```text
1. 为所有原电影镜头构建传统视觉特征
2. 为每个参考镜头构建传统视觉特征
3. 对每个参考镜头召回原电影候选镜头
4. 对候选做局部帧级 refinement
5. 用全局路径算法选择最终匹配结果
```

对应代码位置：

```text
utils/visual_features.py
4_visual_alignment_engine/candidate_recall.py
4_visual_alignment_engine/refinement.py
4_visual_alignment_engine/path_solver.py
4_visual_alignment_engine/diagnostics.py
4_visual_alignment_engine/run.py
```

## 4. 镜头特征构建

特征构建入口：

```python
build_shot_feature()
```

位置：

```text
utils/visual_features.py
```

### 4.1 关键帧选择

每个镜头最多取 `keyframes_per_shot` 张关键帧，默认是 3 张。

选择逻辑：

- 如果关键帧数量小于等于 `max_frames`，全部使用。
- 如果只取 1 张，取中间帧。
- 默认取 3 张时，取首帧、中间帧、尾帧。
- 如果 `max_frames > 3`，按等间距抽帧。

对应函数：

```python
select_keyframes()
```

这意味着当前定位很依赖上游切镜头和关键帧质量。如果参考视频的画面经过裁剪、调色、字幕遮挡、二创缩放、转场叠化，单纯首中尾关键帧很容易代表不了整个镜头。

### 4.2 单帧传统特征

每张关键帧会构建三类特征：

```python
build_frame_feature()
```

包含：

- `dhash`：感知哈希，偏整体结构。
- `hist`：HSV 颜色直方图，偏色彩分布。
- `orb`：ORB 局部特征，偏局部纹理和角点。

如果图片读取失败，该帧返回：

```python
{"ok": False}
```

### 4.3 镜头级相似度

参考镜头和电影镜头之间会对所有关键帧两两比较。

例如参考镜头 3 张关键帧，电影镜头 3 张关键帧，会产生 9 组帧对分数。

入口：

```python
compare_shot_features()
```

单帧完整分数：

```text
score = hash_score * 0.45 + hist_score * 0.35 + orb_score * 0.20
```

轻量分数：

```text
lightweight_score = hash_score * 0.55 + hist_score * 0.45
```

镜头最终分数不是简单平均，而是：

```text
镜头分数 = 最高帧对分数 * 0.6 + Top3 平均分 * 0.4
```

这套逻辑的结果是：只要某一两帧很像，整个镜头就可能被打高分。

## 5. 候选召回

候选召回入口：

```python
build_candidates()
```

位置：

```text
4_visual_alignment_engine/candidate_recall.py
```

对每个 `ref_shot`，流程如下。

### 5.1 第一轮轻量召回

遍历所有 `movie_features`，使用：

```python
compare_shot_features(..., include_orb=False)
```

也就是只看：

- dhash
- hist

不看 ORB。

然后按 `recall_score` 倒序排序，取前 `recall_top_k` 个。

默认：

```text
recall_top_k = 80
```

### 5.2 第二轮完整重排

对召回出来的前 80 个候选，再使用：

```python
compare_shot_features(..., include_orb=True)
```

完整计算：

- dhash
- hist
- ORB

然后按 `visual_score` 倒序排序，取前 `rerank_top_k` 个。

默认：

```text
rerank_top_k = 20
```

每个候选会生成类似字段：

```json
{
  "movie_index": 123,
  "movie_shot_id": "movie_shot_0123",
  "movie_start": 100.0,
  "movie_end": 103.0,
  "visual_score": 0.7123,
  "recall_score": 0.6812,
  "visual_rank": 1,
  "detail": {}
}
```

## 6. 局部帧级 refinement

如果 `alignment_mode != classic`，会进入 refinement。

当前 CLI 默认：

```text
alignment_mode = temporal
```

所以默认会执行 refinement。

入口：

```python
refine_candidates_for_ref()
```

位置：

```text
4_visual_alignment_engine/refinement.py
```

### 6.1 只精修 Top K 候选

虽然每个参考镜头会保留 `rerank_top_k=20` 个候选，但 refinement 默认只处理前：

```text
refine_top_k = 3
```

排名第 4 到第 20 的候选不会做帧级精修，直接保留粗排结果。

### 6.2 参考帧来源

对参考镜头，优先从已有字段取帧：

```text
sample_frames
keyframe_times
keyframes
```

如果帧数量不足 3，并且有 `ref_video_path` 和 `feature_cache_dir`，才会从视频中补抽帧。

每个参考镜头最多保留：

```text
max_ref_frames = 5
```

### 6.3 候选电影帧来源

对候选电影镜头，当前不仅取该候选镜头的帧，还会取邻近镜头的帧。

默认：

```text
neighbor_shot_window = 1
```

也就是候选镜头前后各 1 个镜头的帧也会参与比较。

如果帧数量不足 3，并且有 `movie_video_path` 和 `feature_cache_dir`，会围绕候选时间段补抽帧。

补抽范围：

```text
candidate.movie_start - temporal_radius_sec
candidate.movie_end + temporal_radius_sec
```

当前 CLI 默认：

```text
temporal_radius_sec = 1.5
temporal_step_sec = 1.0
```

每个候选最多保留：

```text
max_movie_frames = 12
```

### 6.4 temporal 模式打分

默认 `temporal` 模式下，每一对参考帧和电影帧会先做归一化：

```python
load_normalized_frame()
```

默认 `spatial_normalize=auto`，会做：

- 裁掉黑边
- 亮度均衡
- 缩放到目标宽度

然后调用：

```python
compare_normalized_frames()
```

帧对分数由以下指标混合：

```text
gray_score * 0.34
edge_score * 0.26
hist_score * 0.18
ssim_score * 0.22
```

其中底部字幕区域会被降权：

```text
subtitle_mask_ratio = 0.18
底部 18% 行权重降为 0.35
```

refinement 会枚举所有参考帧和候选电影帧组合，选择分数最高的一对。

### 6.5 spatial_temporal 模式打分

如果 `alignment_mode=spatial_temporal`，会额外调用：

```python
compare_homography_frames()
```

逻辑是：

- 使用 SIFT，如果没有 SIFT 则使用 ORB。
- 匹配局部特征。
- 用 RANSAC 估计 Homography。
- 将电影帧透视变换到参考帧坐标。
- 再调用 `compare_normalized_frames()`。

最终 refinement 分数：

```text
score = temporal_score * 0.7 + spatial_score * 0.3
```

如果特征点不足、匹配不足或 Homography 失败，会退回普通 temporal 分数。

### 6.6 用最佳帧对反推电影片段时间

找到最佳帧对后，代码会计算参考帧在参考镜头内部的相对位置：

```text
ref_relative = best_ref_time - ref_start
```

然后用最佳电影帧时间反推电影片段起点：

```text
raw_movie_start = best_movie_time - ref_relative
```

再把起点限制在候选窗口内：

```text
window_start = candidate.movie_start - temporal_radius_sec
window_end = candidate.movie_end + temporal_radius_sec
```

最终输出：

```text
movie_start
movie_end = movie_start + ref_duration
```

所以当前输出的电影片段长度基本被参考镜头时长控制，而不是严格使用原电影镜头边界。

### 6.7 refinement 后融合分数

refinement 不会完全替代粗排分数，而是混合：

```text
fused = coarse * 0.45 + temporal_score * 0.40 + spatial_score * 0.15
```

其中：

- `coarse` 是候选原来的 `visual_score`
- `temporal_score` 来自归一化帧比较
- `spatial_score` 在 temporal 模式下等于 temporal 分数

更新后的候选字段包括：

```json
{
  "movie_start": 123.456,
  "movie_end": 125.456,
  "visual_score": 0.8123,
  "coarse_visual_score": 0.7000,
  "refinement_score": 0.9000,
  "refinement": {
    "enabled": true,
    "mode": "temporal",
    "best_ref_time": 1.0,
    "best_movie_time": 124.456,
    "temporal_offset": 123.456,
    "temporal_score": 0.9000,
    "spatial_score": 0.9000
  }
}
```

处理完后，候选会重新按新的 `visual_score` 排序。

## 7. 全局路径求解

候选准备好后，模块会选择每个 `ref_shot` 的最终电影匹配。

入口：

```python
solve_segmented_global_path()
```

位置：

```text
4_visual_alignment_engine/path_solver.py
```

除非 CLI 显式传入：

```text
--disable-global-path
```

否则默认使用分段全局路径。

### 7.1 先过滤候选

对每个参考镜头，先按 `visual_score` 排序。

如果最高分候选满足 anchor 条件，则直接把它作为强锚点：

```text
visual_score >= 0.86
第一名和第二名差值 >= 0.10
refinement_score 或 visual_score >= 0.78
```

anchor 的含义是：这条匹配被认为足够强，允许时间线出现较大跳跃。

如果不是 anchor，并且最高分低于：

```text
min_score * 0.85
```

默认 `min_score=0.35`，所以阈值是：

```text
0.2975
```

该参考镜头会被视为没有可用候选。

### 7.2 分段

过滤后，连续有候选的参考镜头会组成一个 segment。

空候选会切断 segment。

每个 segment 单独做动态规划，不同 segment 之间不做连续性约束。

### 7.3 动态规划路径

每个 segment 内使用：

```python
solve_global_path()
```

它会在每个参考镜头的候选之间做动态规划，目标是最大化累计分数。

单个候选节点分数：

```text
node_score = visual_score * 0.72 + transition_score * 0.28 - path_penalty * 0.25
```

其中 `transition_score` 来自前一个已选候选和当前候选的时间连续性。

### 7.4 时间连续性计算

入口：

```python
transition_metrics()
```

当前会先计算期望电影开始时间：

```text
expected_start = prev.movie_end + ref_gap
```

其中：

```text
ref_gap = current_ref.start - prev_ref.end
```

再计算：

```text
time_delta = current.movie_start - expected_start
continuity_score = exp(-abs(time_delta) / 8.0)
```

惩罚项包括：

```text
backward_penalty
jump_penalty
repeat_penalty
```

#### backward_penalty

如果当前候选开始时间明显早于上一个候选：

```text
current_start < prev_start - 0.5
```

会加倒退惩罚。

#### jump_penalty

如果时间跳跃过大，会加跳跃惩罚。

普通跳跃阈值：

```text
20 秒
```

如果前后有 anchor：

```text
60 秒
```

高视觉分候选和 anchor 会降低跳跃惩罚。

#### repeat_penalty

如果连续两个参考镜头选中了同一个 `movie_shot_id`：

```text
repeat_penalty = 0.18
```

注意：这里只是惩罚，不是禁止重复。

## 8. 手工覆盖

路径求解完成后，才处理人工覆盖。

入口：

```python
_load_manual_overrides()
_manual_candidate()
```

手工覆盖格式支持：

```json
{
  "overrides": [
    {
      "ref_shot_id": "ref_001",
      "movie_shot_id": "movie_123"
    }
  ]
}
```

如果某个 `ref_shot_id` 有覆盖项，会直接用指定 `movie_shot_id` 生成候选，并插入候选列表。

手工覆盖候选的诊断信息会被标记为：

```text
manual_override
```

并且最终 `match_type` 为：

```text
manual_override
```

## 9. timeline 输出构建

最终每个参考镜头会通过：

```python
build_timeline_item()
```

生成一条 `ref_to_movie_timeline`。

位置：

```text
4_visual_alignment_engine/diagnostics.py
```

单条输出主要字段：

```json
{
  "ref_shot_id": "ref_001",
  "ref_start": 0.0,
  "ref_end": 2.0,
  "movie_start": 100.0,
  "movie_end": 102.0,
  "movie_shot_ids": ["movie_123"],
  "match_score": 0.8123,
  "final_score": 0.7900,
  "match_type": "temporal_segmented_global_path",
  "confidence": "medium",
  "status": "matched",
  "diagnostics": {},
  "candidates": []
}
```

### 9.1 confidence 判定

confidence 由 `visual_score`、第一名和第二名分差、路径连续性共同决定。

逻辑：

```text
high:
  visual_score >= 0.82
  score_gap >= 0.08
  path_continuous = true

medium:
  visual_score >= 0.65
  或 visual_score >= 0.45 且 path_continuous = true

low:
  其他情况
```

### 9.2 status 判定

status 逻辑：

```text
candidate 为空:
  unmatched

visual_score < min_score:
  needs_review

confidence = low:
  matched_low_confidence

其他:
  matched
```

注意：`matched_low_confidence` 仍然算作匹配结果，会继续写入 timeline。

### 9.3 accepted_reason

诊断字段里会写入接受原因，例如：

```text
manual_override
no_candidate
visual_score_below_min_score
visual_score_high_and_path_continuous
path_continuity_promoted_candidate
candidate_scores_too_close
accepted_with_path_penalty
visual_score_accepted
```

### 9.4 candidates

每条 timeline 还会保留 Top N 候选。

默认：

```text
top_n = 8
```

这些候选主要用于诊断和人工复核。

## 10. 诊断输出

如果设置了 `diagnostics_dir`，会输出：

```text
diagnostics/low_confidence_report.json
```

包含：

- `confidence == low`
- 或 `status != matched`

的条目。

如果开启：

```text
--save-debug-boards
```

会在：

```text
diagnostics/debug_boards/
```

输出参考帧和电影帧拼接图，用于人工查看 refinement 的最佳帧对。

```python

```

所以 CLI 跑完定位后，默认会调用：


它会为 timeline 中的每个参考镜头创建一个子目录，并裁出：

输出目录：

```text
outputs/4_visual_alignment_engine/matched_shot_clips/
```


## 13. 当前实现的主要脆弱点

以下是从当前代码逻辑直接能看出的风险点。

### 13.1 没有真正的语义视觉模型

当前所谓 `classic_clip` 只是保留参数，实际会回退到 `classic`。

也就是说当前定位主要依赖：

- 感知哈希
- 颜色直方图
- ORB
- 灰度差异
- 边缘差异
- 简化 SSIM

它不理解人物、场景、动作和语义相似性。

### 13.2 首中尾关键帧代表性不足

粗排阶段默认每个镜头只取 3 张关键帧。

如果参考视频的镜头经过：

- 剪辑变速
- 裁剪缩放
- 调色
- 加字幕
- 画中画
- 转场
- 遮罩
- 取自原片镜头中间很短一段

粗排很容易召回不到真正片段。

一旦第一轮 `recall_top_k=80` 没召回正确镜头，后续 refinement 和路径求解都救不回来。

### 13.3 refinement 只处理前三个粗排候选

默认只有 `refine_top_k=3`。

如果真实匹配在粗排第 4 到第 20 名，当前不会被帧级精修，基本很难翻上来。

### 13.4 时间定位由最佳帧对反推，容易偏移

当前 `movie_start` 是通过：

```text
best_movie_time - ref_relative
```

反推出来的。

如果最佳帧对不是同一叙事位置，或者参考视频做过变速、插帧、裁剪，最终片段起点会偏。

### 13.5 时间连续性会推动错误候选

路径求解会把视觉分和时间连续性混合。

当某个候选视觉分一般，但刚好符合前后时间连续性时，可能被路径分数推上来。

诊断里会出现：

```text
path_continuity_promoted_candidate
boosted_by_continuity = true
```

### 13.6 重复镜头没有硬约束

连续选中同一个 `movie_shot_id` 只会加：

```text
repeat_penalty = 0.18
```

并不会禁止重复。

所以多个参考镜头仍然可能匹配到同一个电影镜头。

### 13.7 low confidence 仍会进入下游

`matched_low_confidence` 仍然是 accepted status 之一。

`_summary()` 里也把它算进 matched：

```python
{"matched", "matched_low_confidence", "inferred_by_neighbors"}
```

所以下游如果不额外过滤，低置信匹配也会继续参与后续流程。

### 13.8 分数阈值整体偏宽

默认 `min_score=0.35`。

分段路径过滤里实际用的是：

```text
min_score * 0.85 = 0.2975
```

这会让很多弱候选进入路径求解。

### 13.9 anchor 可能允许大跳跃

如果某个候选满足 anchor 条件，路径求解会允许它打断正常连续性。

这对强匹配有帮助，但如果 anchor 被误判，会直接造成时间线大跳。

### 13.10 导出匹配片段默认开启

`EXPORT_MATCHED_SHOT_CLIPS = True` 会导致每次定位后都裁片段。

这对排查有帮助，但会增加运行时间和磁盘占用。

## 14. 一句话总结

当前画面定位不是端到端视频检索，也不是语义级片段对齐，而是一套基于传统视觉特征的启发式流程：

```text
关键帧传统特征粗召回
  -> Top K 候选重排
  -> 少量候选做帧级局部精修
  -> 用时间连续性动态规划选路径
  -> 输出 timeline 和诊断字段
```

它能在参考视频和原电影画面差异较小、镜头切分稳定、关键帧质量较好时工作；但面对二创剪辑、字幕遮挡、缩放裁剪、变速、转场、重复场景和弱纹理画面时，当前逻辑很容易出现错配、偏移和低置信结果继续流入下游的问题。
