# 原声片段识别模块改造方案

本文档用于把“原声片段识别模块”落到当前 `movie-recap-clone` 项目里，而不是重新设计一套脱离代码的流程。

核心目标：

```txt
在现有 1-8 阶段流水线中，识别哪些片段应该保留原电影原声，哪些片段应该生成新解说配音。
```

这个模块不负责重新定位画面，不负责生成新文案，也不负责渲染视频。它只在已经完成画面绑定后，为 `script_mapping` 增加可复查的音频决策字段。

---

## 1. 当前项目真实流程

当前 `main.py` 的流水线是：

```txt
1_reference_analyzer
  输入 ref_video_path / subtitle_srt
  输出 outputs/1_reference_analyzer/ref_analysis.json
       outputs/1_reference_analyzer/ref_subtitle.srt

2_narration_segmenter
  输入 ref_analysis.json
  输出 outputs/2_narration_segmenter/narration_segments.json

3_movie_shot_parser
  输入 movie_path
  输出 outputs/3_movie_shot_parser/movie_shots.json

4_visual_alignment_engine
  输入 ref_analysis.json + movie_shots.json
  输出 outputs/4_visual_alignment_engine/ref_to_movie_timeline.json

5_script_visual_binder
  输入 narration_segments.json + ref_to_movie_timeline.json
  输出 outputs/5_script_visual_binder/script_mapping.json

6_rewrite_engine
  输入 script_mapping.json
  输出 outputs/6_rewrite_engine/rewritten_script.json

7_timeline_composer
  输入 rewritten_script.json + script_mapping.json + movie_shots.json
  输出 outputs/7_timeline_composer/final_timeline.json

8_generate_video
  输入 final_timeline.json
  输出剪映草稿或渲染视频
```

其中第 5 步当前输出的 `script_mapping` 只有：

```json
{
  "segment_id": "seg_001",
  "old_text": "职场如战场而他是那个最没用的炮灰...",
  "ref_time_range": {
    "start": 0.0,
    "end": 17.69
  },
  "movie_time_ranges": [
    {
      "start": 149.22,
      "end": 152.587,
      "source_ref_shot_id": "ref_shot_001",
      "movie_shot_ids": ["movie_shot_000038"],
      "confidence": "high",
      "match_score": 0.9923
    }
  ],
  "text_role": "hook"
}
```

这个结构能表达“用哪些原电影画面”，但不能表达“这一段该不该保留原电影声音”。

---

## 2. 新模块放在哪里

新增模块放在第 5 步之后、第 6 步之前：

```txt
5_script_visual_binder
  ↓
原声片段识别模块
  ↓
6_rewrite_engine
```

推荐先不重排现有目录编号，减少改造面：

```txt
新增目录：
  5_audio_role_classifier/run.py

新增输出：
  outputs/5_audio_role_classifier/script_mapping_with_audio.json
```

然后把 `main.py` 中第 6 步的输入从：

```txt
outputs/5_script_visual_binder/script_mapping.json
```

改为：

```txt
outputs/5_audio_role_classifier/script_mapping_with_audio.json
```

第 7 步的 `--script-mapping` 也应改为增强后的 `script_mapping_with_audio.json`，这样时间轴模块能拿到音频决策。

---

## 3. 模块职责边界

原声片段识别模块只做三件事：

```txt
1. 给每个 movie_time_range 补充原电影字幕片段 movie_subtitles。
2. 把参考视频字幕拆成可判断的 text_units。
3. 判断每个 text_unit / movie_time_range 是解说覆盖，还是保留原片原声。
```

它明确不做：

```txt
1. 不改 movie_time_ranges 的 start/end。
2. 不重新做 ref_shot 到 movie_shot 的画面匹配。
3. 不生成新文案。
4. 不直接剪辑或渲染视频。
```

也就是说，画面定位结果仍由 `4_visual_alignment_engine` 和 `5_script_visual_binder` 决定；原声模块只在这些结果上增加音频策略。

---

## 4. 为什么不能只看 old_text

当前 `2_narration_segmenter/run.py` 会把多个 SRT 字幕直接拼接成 `text`：

```python
"".join(str(x.get("text") or "").strip() for x in current)
```

所以 `old_text` 常常长这样：

```txt
职场如战场而他是那个最没用的炮灰工作没起色爱情没回复每天只有无尽的加班和经理的冷嘲热讽因为你业绩差又不努力我不努力我只是没能力从小到大，我最会的一件事情就是拼命
```

这里面混有两类内容：

```txt
解说旁白：
  职场如战场而他是那个最没用的炮灰
  工作没起色爱情没回复

原片对白：
  因为你业绩差又不努力
  我不努力我只是没能力
  从小到大，我最会的一件事情就是拼命
```

因此新模块不能直接让 LLM 对整段 `old_text` 猜测。更稳的做法是回到参考视频 SRT 明细，使用 `utils.subtitle_tools.parse_srt()` 重新拿到字幕粒度。

## 5. 新模块输入

建议 CLI：

```powershell
python .\5_audio_role_classifier\run.py `
  --script-mapping .\outputs\5_script_visual_binder\script_mapping.json `
  --ref-analysis .\outputs\1_reference_analyzer\ref_analysis.json `
  --movie-path "D:\path\movie.mp4" `
  --output-dir .\outputs\5_audio_role_classifier `
  --movie-subtitle-srt "D:\path\movie.srt"
```

`--movie-subtitle-srt` 可选。没有原电影字幕时，模块可以复用当前项目已有能力：

```txt
utils.subtitle_tools.extract_srt_with_bcut()
```

也就是从 `movie_path` 抽音频后用 Bcut ASR 生成 `movie_subtitle.srt`。

输入文件来源：

| 输入 | 当前已有位置 | 用途 |
| --- | --- | --- |
| `script_mapping.json` | `outputs/5_script_visual_binder` | 已完成的段落和画面绑定 |
| `ref_analysis.json` | `outputs/1_reference_analyzer` | 获取 `subtitle_srt` 路径 |
| `ref_subtitle.srt` | `outputs/1_reference_analyzer` | 拆出参考字幕明细 |
| `movie_subtitle.srt` | 用户传入或本模块生成 | 裁出每个电影时间段的原片对白 |
| `movie_path` | `main.py --movie-path` | 没有电影字幕时用于 ASR |

## 8. text_units 结构

`text_units` 不建议从 `old_text` 硬切。推荐从 `ref_subtitle.srt` 中裁出与 `ref_time_range` 重叠的字幕行。

示例：

```json
{
  "unit_id": "seg_001_unit_001",
  "source_ref_subtitle_index": 1,
  "ref_start": 0.0,
  "ref_end": 3.2,
  "text": "职场如战场而他是那个最没用的炮灰",
  "role": "narration",
  "action": "rewrite",
  "related_range_ids": ["seg_001_range_001"],
  "matched_movie_subtitles": [],
  "confidence": 0.92,
  "reason": "第三方概括人物处境，未在原电影字幕中找到相似对白"
}
```

对白示例：

```json
{
  "unit_id": "seg_001_unit_004",
  "source_ref_subtitle_index": 4,
  "ref_start": 11.2,
  "ref_end": 13.1,

  "role": "original_dialogue",
  "action": "play_original_audio",
  "related_range_ids": ["seg_001_range_004"],

    {
      "start": 345.1,

  ],

  "reason": "参考字幕与原电影字幕文本一致"
}
```

## 9. 字段枚举

`audio_role` 建议控制在这些值：

| 值 | 含义 |
| --- | --- |
| `narration_overlay` | 新解说覆盖原片声音 |
| `original_dialogue` | 保留原电影对白 |
| `original_sound_effect` | 保留原电影音效，如爆炸、哭声、尖叫、打斗声 |
| `mixed_narration_and_dialogue` | 新解说和低音量原声混合 |
| `silent_visual` | 只保留画面，不播放原声，也不生成配音 |
| `unknown` | 无法判断，需要人工审核或按默认策略处理 |

`audio_action` 建议控制在这些值：

| 值 | 后续行为 |
| --- | --- |
| `rewrite_and_voiceover` | 参与仿写并生成 TTS，原片声音静音 |
| `play_original_audio` | 不生成 TTS，保留原片声音 |
| `play_original_audio_low_volume` | 生成 TTS，同时把原片声音降音量混入 |
| `mute_original_audio` | 原片声音静音，可能也不生成 TTS |
| `manual_review` | 标记人工复查 |

`segment_audio_role` 可以从 range 聚合得到：

```txt
全部 rewrite_and_voiceover => narration_overlay
全部 play_original_audio   => original_dialogue
同时存在两者              => mixed
存在 manual_review         => manual_review
```

## 10. 判断逻辑

推荐采用“规则优先，LLM 兜底”的策略。

### 10.1 规则判断

先对参考字幕和原电影字幕做归一化：

```txt
1. 去掉空白、标点、引号。
2. 全角半角统一。
3. 中文数字和阿拉伯数字可暂不强制转换，后续再优化。
```

然后计算相似度，可以先用 Python 标准库：

```python
from difflib import SequenceMatcher

score = SequenceMatcher(None, ref_text_norm, movie_text_norm).ratio()
```

建议阈值：

| 条件 | 判定 |
| --- | --- |
| 相似度 `>= 0.82` | `original_dialogue` |
| 相似度 `0.65 - 0.82` | 进入 LLM 兜底 |
| 没有 movie_subtitles | 默认 `narration_overlay` |
| movie_subtitles 很短且只命中 1-2 个字 | 不直接判原声，进入 LLM 或默认解说 |

### 10.2 LLM 兜底

只把模糊片段交给 LLM，避免成本和不稳定性扩大。

输入给 LLM 的最小上下文：

```json
{
  "segment_id": "seg_001",
  "old_text": "职场如战场而他是那个最没用的炮灰...",
  "ref_subtitles": [
    {
      "unit_id": "seg_001_unit_001",
      "start": 0.0,
      "end": 3.2,
      "text": "职场如战场而他是那个最没用的炮灰"
    }
  ],
  "movie_time_ranges": [
    {
      "range_id": "seg_001_range_004",
      "start": 344.37,
      "end": 352.585,
      "movie_subtitles": [
        {
          "start": 345.1,
          "end": 347.4,
          "text": "因为你业绩差又不努力"
        }
      ]
    }
  ]
}
```

让 LLM 只输出结构化 JSON：

```json
{
  "text_units": [
    {
      "unit_id": "seg_001_unit_004",
      "role": "original_dialogue",
      "action": "play_original_audio",
      "related_range_ids": ["seg_001_range_004"],
      "confidence": 0.95,
      "reason": "与原电影字幕内容一致"
    }
  ],
  "range_audio_decisions": [
    {
      "range_id": "seg_001_range_004",
      "audio_role": "original_dialogue",
      "audio_action": "play_original_audio",
      "confidence": 0.95,
      "reason": "该 range 内存在与参考字幕一致的对白"
    }
  ]
}
```

约束 prompt：

```txt
你是影视解说音频角色识别器。
你只能判断字幕和音频策略，不能修改画面时间。
如果参考字幕与原电影字幕高度相似，判为 original_dialogue。
如果参考字幕是第三方叙述、剧情概括、悬念包装，判为 narration。
无法判断时输出 unknown/manual_review。
必须只输出 JSON。
```

## 11. 对 rewrite_engine 的改造

当前 `6_rewrite_engine/run.py` 的输入构造只关心：

```txt
segment_id
old_text
text_role
ref_time_range
movie_time_ranges
```

改造后应优先读取：

```txt
text_units
segment_audio_role
movie_time_ranges[*].audio_action
```

仿写规则：

```txt
1. role = narration 的 text_units 参与仿写。
2. role = original_dialogue 的 text_units 不仿写。
3. action = play_original_audio 的 range 不因为新文案时长被当成解说画面压缩。
4. mixed segment 输出 rewritten_units，不能只输出一个 new_text。
```

推荐 `rewritten_script.json` 增强为：

```json
{
  "rewritten_script": [
    {
      "segment_id": "seg_001",
      "old_text": "职场如战场而他是那个最没用的炮灰...",
      "new_text": "在这个吃人的职场里，他像个随时会被丢掉的小角色...",
      "segment_audio_role": "mixed",
      "rewritten_units": [
        {
          "unit_id": "seg_001_unit_001",
          "role": "narration",
          "old_text": "职场如战场而他是那个最没用的炮灰",
          "new_text": "在这个吃人的职场里，他像个随时会被丢掉的小角色"
        },
        {
          "unit_id": "seg_001_unit_004",
          "role": "original_dialogue",
          "old_text": "因为你业绩差又不努力",
          "new_text": "",
          "keep_original_audio": true
        }
      ],
      "movie_time_ranges": []
    }
  ]
}
```

兼容策略：

```txt
如果 script_mapping 没有 text_units：
  保持当前逻辑，整段 old_text -> new_text。

如果 text_units 存在：
  只把 narration units 送入 LLM。
```

## 12. 对 timeline_composer 的改造

当前 `7_timeline_composer/run.py` 是“一段 rewritten_script 生成一个 final_timeline item”。

原声模块加入后，混合段落需要拆成多个 item：

```txt
narration units + rewrite ranges     => voiceover item
original_dialogue ranges             => original item
mixed_narration_and_dialogue ranges  => mixed item
```

推荐 `final_timeline.json` 增强字段：

```json
{
  "item_id": "item_002",
  "segment_id": "seg_001",
  "audio_mode": "original",
  "OST": 1,
  "narration": "",
  "timeline_start": 8.788,
  "timeline_end": 17.003,
  "video_clips": [
    {
      "clip_id": "clip_001",
      "movie_start": 344.37,
      "movie_end": 352.585,
      "duration": 8.215,
      "source": "D:\\path\\movie.mp4",
      "source_ref_shot_id": "ref_shot_004",
      "movie_shot_ids": ["movie_shot_000076"],
      "keep_original_audio": true,
      "allocation": "original_audio"
    }
  ],
  "audio_decision": {
    "audio_role": "original_dialogue",
    "audio_action": "play_original_audio",
    "source_range_ids": ["seg_001_range_004"]
  }
}
```

解说 item 示例：

```json
{
  "item_id": "item_001",
  "segment_id": "seg_001",
  "audio_mode": "voiceover",
  "OST": 0,
  "narration": "在这个吃人的职场里，他像个随时会被丢掉的小角色。",
  "video_clips": [
    {
      "movie_start": 149.22,
      "movie_end": 152.587,
      "keep_original_audio": false
    }
  ],
  "audio_decision": {
    "audio_role": "narration_overlay",
    "audio_action": "rewrite_and_voiceover"
  }
}
```

`OST` 字段是为了兼容项目里已有的生成服务语义：`utils/generate_video/video_generation_service.py` 中已经用 `OST == 1` 或 `text.startswith("播放原片")` 表示跳过 TTS、播放原片。

## 13. 对 generate_video 的改造

这是最容易忽略的一点：只改 `script_mapping` 和 `final_timeline` 不够。

当前 `8_generate_video/run.py` 的 CLI 渲染路径会：

```txt
1. 为每个 final_timeline item 合成音频。
2. 裁视频时使用 -an 去掉原视频音频。
3. 把 TTS 或静音音频 mux 到视频上。
```

所以如果不改第 8 步，即使 `final_timeline` 标了 `audio_mode: original`，最终也听不到原片原声。

第 8 步需要支持：

```txt
audio_mode = voiceover:
  当前逻辑，裁视频去原声，合成 TTS，再 mux。

audio_mode = original:
  不生成 TTS。
  裁视频时保留原视频音频。
  该 item 直接使用原片音轨。

audio_mode = silent:
  不生成 TTS。
  裁视频去原声，mux 静音或直接无音轨。

audio_mode = mixed:
  生成 TTS。
  裁视频保留原声并降音量。
  与 TTS 混音后输出。
```

最小 MVP 可先只支持：

```txt
voiceover
original
```

对应代码改动点：

| 文件 | 改动 |
| --- | --- |
| `8_generate_video/run.py` | `_synthesize_one()` 对 `audio_mode=original` 跳过 TTS |
| `8_generate_video/run.py` | `_cut_video_clip()` 增加 `keep_audio` 参数 |
| `8_generate_video/run.py` | `render_video()` 中 original item 不走 `_mux_item_with_audio()` |
| `8_generate_video/run.py` | `generate_jianying_draft()` 中 original item 不额外添加 TTS 音频轨 |

## 14. 推荐实现步骤

### 阶段一：只产出音频决策，不改变渲染

新增：

```txt
5_audio_role_classifier/run.py
```

实现：

```txt
1. 读取 script_mapping.json。
2. 解析 ref_subtitle.srt。
3. 获取或生成 movie_subtitle.srt。
4. 为每个 segment 补 text_units。
```

## 17. 默认策略

为了避免误把解说当原声，建议默认策略保守：

```txt
没有原电影字幕 => narration_overlay
相似度不够高 => narration_overlay 或 manual_review
LLM 无法判断 => manual_review
用户不启用原声模块 => 完全保持当前 1-8 流程
```

也就是说，原声模块启用后最坏情况应该退回现有“全部解说覆盖”的行为，而不是生成不可控的原声混入。

## 18. 最终数据流

改造完成后的目标数据流：

```txt
ref_subtitle.srt
    ↓
text_units

movie_subtitle.srt
    ↓
movie_time_ranges[*].movie_subtitles

script_mapping.json
    ↓
script_mapping_with_audio.json
    ↓
rewritten_script.json
    ↓
final_timeline.json(audio_mode / OST)
    ↓
8_generate_video 根据 audio_mode 决定 TTS、静音、保留原声
```

这个设计能保证：

```txt
画面定位结果稳定；
原片对白不会被误改写成解说；
真正的解说内容仍能进入仿稿模块；
最终时间轴能清楚表达 voiceover 和 original audio；
现有项目的 script_mapping / final_timeline 主链路不被打断。
```
