# 五、核心拼接逻辑

这个分支的核心不是文案，而是：

```txt
参考视频时间段 ref_start ~ ref_end
        ↓
取参考视频这一段音频
        ↓
找到对应原电影画面 movie_start ~ movie_end
        ↓
用原电影画面替换参考视频画面
        ↓
保留参考视频音频
```

简单来说：

```txt
音频来自 ref_video
画面来自 movie
时间结构来自 ref_to_movie_timeline
```

# 六、最小可行拼接规则

不要做复杂，直接按 `ref_to_movie_timeline` 的每条 matched 结果生成一个 clip。

## 规则 1：只处理 matched 的镜头

```txt
status = matched
confidence = high / medium
```

可以进入重构。

```txt
status = unmatched
```

暂时跳过，或者用参考视频原画面兜底。

建议 MVP 先跳过或标记，不要强行补。

---

## 规则 2：音频时间使用参考视频时间

```json
{
  "audio_source": "ref_video",
  "audio_start": 0.0,
  "audio_end": 3.367
}
```

---

## 规则 3：视频时间使用原电影时间

```json
{
  "video_source": "movie",
  "video_start": 149.643,
  "video_end": 153.01
}
```

---

## 规则 4：默认不改变参考视频音频时长

参考视频这一段音频时长是：

```txt
ref_duration = ref_end - ref_start
```

原电影画面片段时长是：

```txt
movie_duration = movie_end - movie_start
```

正常情况下两者接近，但可能有误差。

建议不要复杂处理，使用下面规则：

```txt
以 ref_duration 为最终时长。
```

也就是说：

```txt
最终片段时长 = 参考视频音频时长
```

然后处理原电影画面：

```txt
如果 movie_duration > ref_duration：
  裁掉 movie 画面尾部

如果 movie_duration < ref_duration：
  向后扩展 movie_end

如果仍然不够：
  允许最后一帧轻微冻结，或者标记 low_confidence
```

# 七、增加一个简单的拆分拼接策略

你说这里仍然需要设计一个拆分拼接逻辑。建议不要按字幕拆，直接按 **定位后的 ref_shot 结果** 拆。

也就是：

```txt
一个 ref_shot 对应一个 rebuild_clip
```

但是为了避免生成太碎，可以加一个合并规则。

---

## 7.1 基础拆分

原始输入：

```txt
ref_shot_001 -> movie 149.643 ~ 153.01
ref_shot_002 -> movie 155.722 ~ 157.978
ref_shot_003 -> movie 160.234 ~ 163.399
```

初始生成：

```txt
clip_001
clip_002
clip_003
```

---

## 7.2 相邻片段合并

如果两个片段在参考视频里是连续的，并且在原电影里也近似连续，就可以合并。

判断规则：

```txt
ref_gap = next.ref_start - current.ref_end
movie_gap = next.movie_start - current.movie_end
```

如果满足：

```txt
ref_gap <= 0.3s
movie_gap >= -0.2s 且 movie_gap <= 1.0s
```

就可以合并成一个更大的片段。

---

## 7.3 为什么要合并

因为如果每个镜头都单独切，会有几个问题：

```txt
1. 剪映轨道太碎
2. 音频容易出现微小断裂
3. 视频转场不自然
4. 后期不好调
```

所以建议：

```txt
先按 ref_shot 拆
再按连续性合并
最后输出 rebuild_segments
```

# 十、时长对齐策略

这是这个分支最需要注意的地方。

因为你是：

```txt
参考视频音频 + 原电影画面
```

所以最终时间必须以 **参考视频音频时长** 为准。

---

## 10.1 单个 clip 对齐

```txt
target_duration = ref_end - ref_start
movie_duration = movie_end - movie_start
```

### 情况 1：movie_duration 接近 target_duration

```txt
直接使用 movie_start ~ movie_end
```

---

### 情况 2：movie_duration 太长

```txt
从 movie_start 开始，裁到 target_duration
```

示例：

```txt
ref:   0.0 ~ 3.0，时长 3s
movie: 100.0 ~ 104.5，时长 4.5s

最终：
movie: 100.0 ~ 103.0
```

---

### 情况 3：movie_duration 太短

```txt
优先向后扩展 movie_end
```

示例：

```txt
ref:   0.0 ~ 4.0，时长 4s
movie: 100.0 ~ 102.8，时长 2.8s

最终：
movie: 100.0 ~ 104.0
```

如果扩展超过下一个镜头太多，可以标记：

```json
{
  "fit_mode": "extend_movie_end",
  "duration_warning": "movie_clip_short"
}
```

# 十四、这个模块的核心处理步骤

```txt
4.1_ref_audio_rebuild_composer

输入：
  - ref_to_movie_timeline.json
  - ref_video_path
  - movie_path

处理：
  1. 读取 ref_to_movie_timeline
  2. 按 ref_start 从小到大排序
  3. 过滤 status = matched 的片段
  4. 根据 ref_start/ref_end 取参考视频音频
  5. 根据 movie_start/movie_end 取原电影画面
  6. 以 ref_duration 为准对齐画面时长
  7. 相邻片段可以合并
  8. unmatched 片段用 ref_video 原画面兜底
  9. 输出 ref_audio_rebuild_timeline.json

输出：
  - ref_audio_rebuild_timeline.json
```
