# 原声片段识别模块剩余工作清单

本文档记录当前原声片段识别链路已完成内容，以及从现在到真正可听到“保留原片原声”还需要完成的工作。

## 当前状态

已完成：

1. `5_audio_role_classifier`
   - 已能读取 `script_mapping.json`、`ref_analysis.json`。
   - 已能使用 `parse_srt(subtitle_srt)` 拆参考视频字幕为 `text_units`。
   - 已能给 `movie_time_ranges` 补 `movie_subtitles`、`audio_role`、`audio_action`、`audio_confidence`、`audio_reason`。
   - 已输出 `script_mapping_with_audio.json`。

2. `6_rewrite_engine`
   - 已支持 `text_units`。
   - 已只仿写 `role=narration` 的单元。
   - 已让 `original_dialogue / play_original_audio` 单元输出空 `new_text`，并标记 `keep_original_audio=true`。
   - 已输出 `rewritten_units`。

3. `7_timeline_composer`
   - 已支持按 `rewritten_units` 和 `movie_time_ranges[*].audio_action` 拆分 mixed segment。
   - 已给 `final_timeline` item 增加 `audio_mode`、`OST`、`audio_decision`。
   - 已让 `audio_mode=original` 的 item 时长直接等于原片 clip duration，不按字数估算 TTS。

4. `main.py`
   - 已支持可选启用 `--enable-audio-role-classifier`。
   - 已支持 `--only-step` 单步执行。

目前最大缺口：

```txt
final_timeline.json 已经能标出 audio_mode=original，
但 8_generate_video 还没有真正按 audio_mode 渲染音频。
```

也就是说，当前即使第 7 步输出了 `audio_mode=original`，第 8 步仍可能：

1. 给空 narration 生成静音音频。
2. 裁视频时使用 `-an` 去掉原视频音轨。
3. 再把静音音频 mux 回去。

结果就是：时间轴数据看起来对了，但最终视频仍听不到原片原声。

## P0：必须完成的核心工作

### 1. 改造 `8_generate_video/run.py` 的 TTS 合成逻辑

目标：

```txt
audio_mode=voiceover => 继续合成 TTS
audio_mode=original  => 不合成 TTS，也不生成静音音频
```

建议改动点：

1. `_synthesize_one()`
   - 当前 `narration` 为空时会生成静音 mp3。
   - 需要先判断 `item.get("audio_mode") == "original"`。
   - original item 应直接返回类似：

```json
{
  "path": "",
  "duration": 3.215,
  "original_audio": true,
  "silent": false
}
```

2. `synthesize_timeline_audio()`
   - 允许 original item 没有真实音频文件路径。
   - 打印日志时区分 TTS / original audio。

验收标准：

```txt
audio_mode=original 的 item 不调用 Edge TTS。
audio_mode=original 的 item 不生成静音 mp3。
audio_results 中能明确标记 original_audio=true。
```

### 2. 改造视频裁剪逻辑，支持保留原音轨

目标：

```txt
voiceover item 裁视频时去掉原声
original item 裁视频时保留原声
```

建议改动点：

1. `_cut_video_clip()`
   - 增加参数：

```python
def _cut_video_clip(..., keep_audio: bool = False, audio_volume: float = 1.0)
```

2. 当 `keep_audio=False`
   - 保持当前行为：`-map 0:v:0 -an`。

3. 当 `keep_audio=True`
   - 需要同时 map 视频和音频：

```txt
-map 0:v:0
-map 0:a?
```

   - 使用 `0:a?` 是为了源视频没有音轨时不直接失败。
   - 输出参数需要包含音频编码：

```txt
-c:a aac
-b:a 192k
-ar 48000
```

4. 如果后续支持 mixed，需要支持音量：

```txt
-filter_complex 或 -af volume=0.35
```

MVP 阶段可以先只实现 `keep_audio=True/False`，不做 mixed 音量。

验收标准：

```txt
audio_mode=original 的 clip 输出文件包含音轨。
audio_mode=voiceover 的 clip 输出文件不保留原音轨。
无音轨原视频不会导致 ffmpeg 失败。
```

### 3. 改造 `render_video()` 的 item 渲染分支

目标：

```txt
voiceover item => 当前逻辑：裁视频去原声，TTS mux 到视频上
original item  => 裁视频保留原声，不再 mux TTS/静音音频
```

建议改动点：

1. `render_video()`
   - 每个 item 先取：

```python
audio_mode = item.get("audio_mode") or "voiceover"
```

2. `audio_mode=voiceover`
   - 继续使用当前逻辑：
     - 从 `audio_results[key]` 获取 TTS。
     - `_retime_clips_to_audio(item, audio_duration)`。
     - `_cut_video_clip(..., keep_audio=False)`。
     - `_mux_item_with_audio(...)`。

3. `audio_mode=original`
   - 不使用 `_mux_item_with_audio()`。
   - 不根据 TTS 时长 `_retime_clips_to_audio()`。
   - 使用 `item["video_clips"]` 原始时长。
   - 裁剪时 `_cut_video_clip(..., keep_audio=True)`。
   - 多 clip 时直接 `_concat_videos(clip_paths, item_path, reencode=True)`。

4. final concat
   - 最终 `_concat_videos(item_paths, output_path, reencode=True)` 已经会输出音频，应继续保留。

验收标准：

```txt
original item 不走 _mux_item_with_audio。
original item 的视频片段时长不被 TTS duration 改写。
最终 mp4 中 original item 能听到原片音频。
voiceover item 行为不回退。
```

### 4. 改造剪映草稿生成逻辑

目标：

```txt
voiceover item => 视频轨静音，额外添加 TTS 音频轨
original item  => 视频轨保留原声，不添加 TTS 音频轨
```

建议改动点：

1. `generate_jianying_draft()`
   - 当前所有 video segment 都写死：

```json
"volume": 0
```

   - 需要按 item 判断：

```txt
audio_mode=voiceover => volume=0
audio_mode=original  => volume=1
```

2. original item 不应复制 `audio_results[key]["path"]`。
3. original item 不应向 `audio_segments` 添加配音轨。
4. original item 的 `item_duration_us` 应直接由 video clips 累加。

验收标准：

```txt
剪映草稿中 original item 的视频轨有原声。
剪映草稿中 original item 没有额外静音/TTS 音频素材。
voiceover item 仍有 TTS 音频轨，且视频轨静音。
```

## P1：需要完善但不阻塞 MVP 的工作

### 1. 支持 `audio_mode=mixed`

当前第 7 步已经可能输出 `audio_mode=mixed`，但第 8 步还没有真正混音。

目标：

```txt
mixed item:
  1. 生成 TTS。
  2. 裁视频时保留原声。
  3. 原声降音量。
  4. 与 TTS 混音输出。
```

建议实现：

1. `_cut_video_clip(..., keep_audio=True, audio_volume=0.35)`。
2. 新增 `_mux_item_with_mixed_audio()`。
3. ffmpeg filter 示例：

```txt
[0:a]volume=0.35[a0];
[1:a]volume=1.0[a1];
[a0][a1]amix=inputs=2:duration=longest:dropout_transition=0[a]
```

验收标准：

```txt
mixed item 既能听到 TTS，也能低音量听到原片声音。
mixed item 不影响 voiceover / original 的行为。
```

### 2. 支持 `audio_mode=silent`

目前设计里有 silent，但前面阶段还没有重点产出该模式。

目标：

```txt
silent item:
  不生成 TTS。
  裁视频去原声。
  最终 item 可以无音轨或静音音轨。
```

验收标准：

```txt
silent item 不调用 TTS。
silent item 不保留原片音频。
最终拼接不因无音轨片段失败。
```

### 3. LLM 兜底识别

当前 `5_audio_role_classifier` 是规则优先、偏保守。

实现约束：

```python
from clone_narration_video.utils.ai import AIModelConfig, ChatMessage, CustomOpenAIProvider
```

后续所有大模型调用都应复用这套项目内已有封装，参考 `6_rewrite_engine/run.py` 的调用方式，不要在原声模块里重新引入新的 OpenAI SDK 客户端、requests 调用或另一套配置读取逻辑。

剩余需求：

1. 对相似度 `0.65 - 0.82` 的片段调用 LLM。
2. LLM 只判断音频角色，不修改画面时间。
3. LLM 输出必须结构化：

```json
{
  "text_units": [],
  "range_audio_decisions": []
}
```

4. LLM 失败时回退：

```txt
manual_review 或 narration_overlay
```

验收标准：

```txt
模糊对白能进入 LLM 判断。
LLM 不会扩大改写范围。
LLM 失败不会导致不可控的原声混入。
```

### 4. `manual_review` 的产品化处理

当前 `manual_review` 更像数据标记，后续模块还没有完整产品策略。

需要明确：

```txt

是否在前端显示待复核片段？
是否允许用户手动改 audio_action？
```

推荐 MVP 策略：

```txt

但保留 audio_decision 供用户检查。
```

### 5. 前端/桌面端接入

当前 CLI 已有 `--enable-audio-role-classifier`，但前端流程可能还没有完整入口。

剩余需求：

## P2：质量和体验增强

### 1. 原电影字幕获取优化

当前如果没有 `--movie-subtitle-srt`，需要自动识别原电影字幕。

可优化：

1. 优先复用已有 `outputs/5_audio_role_classifier/movie_subtitle.srt`。
2. 支持只识别命中的 movie ranges，而不是整部电影。
3. ASR 网络失败时显示更明确的解决建议。
4. 支持用户传入已有 SRT 后跳过 ASR。

### 2. 识别规则增强

可优化：

1. 更好的中文归一化：
   - 繁简转换。
   - 中文数字和阿拉伯数字统一。
   - 英文大小写和缩写处理。

2. 更好的相似度策略：
   - 多字幕行滑窗匹配。
   - 长句拆短句匹配。
   - 避免 1-2 个字误判原声。

3. 原声音效识别：
   - `original_sound_effect`
   - 尖叫、爆炸、打斗声、哭声等无对白但应保留的片段。

### 3. 统计报告

建议在 `script_mapping_with_audio.json` 或单独报告里增加统计：

```json
{
  "segments_total": 100,
  "ranges_total": 350,
  "voiceover_ranges": 300,
  "original_ranges": 42,
  "manual_review_ranges": 8,
  "original_duration": 96.2
}
```

用途：

```txt
让用户在渲染前知道会保留多少原声。
方便发现误判比例异常。
```

### 4. 可视化审核

后续可做一个审核视图：

```txt

movie_subtitles
audio_role/audio_action

```

允许用户手动切换：


## MVP 完成定义

可以认为原声模块 MVP 完成，当且仅当：

```txt
1. 5_audio_role_classifier 能输出 script_mapping_with_audio.json。
2. 6_rewrite_engine 能输出 rewritten_units，并跳过 original_dialogue 文案。
3. 7_timeline_composer 能输出 audio_mode=original 的 final_timeline item。
4. 8_generate_video 能让 audio_mode=original 的 item 保留原片声音。
5. voiceover item 的旧 TTS 流程不回退。
6. 有自动化测试证明 original item 不调用 TTS、不静音原片、不按字数估算 duration。
```

当前已满足 1、2、3；剩余最关键的是 4、5、6。
